# LTX: v0.11.2 vs v0.11.3 (2026-10-20)

RTX 5090, plaintext models, CLI from source (not a release build), one 40 s 1080p video with one
mosaic track (12 windows at 512, Sharper large mosaics off). Old = tag `v0.11.2` (`b623466`), new =
main `a12441c`; runs alternated old/new, two each.

| | v0.11.2 High | v0.11.3 High | v0.11.3 Standard (new default) |
|---|---|---|---|
| Whole job | 110.8 s | 81.6 s (1.36x faster) | 47.0 s (2.36x faster than v0.11.2's default) |
| Scan | 3.5 s | 3.5 s | 3.4 s |
| Encode | 7.4 s (0.45 s/window) | 7.8 s (0.36 s/window) | 7.8 s |
| Denoise | 63.7 s (0.49 s/step) | 52.7 s (0.49 s/step) | 16.8 s |
| Compose | 32.7 s | 13.4 s | 13.1 s |

Denoise per step is unchanged; v0.11.2 spends ~16 s more loading the transformer per job. Encode is
20 % faster per window but its warm-up eats that on 12 windows. The in-job decode line barely moves
(1.0 vs 0.97 s/window) because decode now overlaps compositing; the gain shows in compose. Release
builds add the protected-load and worker-start changes, not measured here.

Relative model speed (owner's GUI runs on main, same video, LTX time; long videos per window):
Standard 1x, Good 1.3x (512) / 1.6x (768) / ~1.5x per window, High 2.0x / 2.4x / ~2.4x, Top 4.1x /
5.0x / ~5x.
